# Phase 6: AI Coding-Agent Build Pack

## Purpose

Phase 6 extends AI-Assisted Project Planner from planning and prompt handoff into deterministic coding-agent job package preparation.

The feature helps users start from a short project idea and produce implementation-oriented markdown documents that can be reviewed by engineers and used with coding agents such as Codex, Claude Code, Cursor, GitHub Copilot, Lovable, Bolt, Gemini, or similar tools.

The system does not build, deploy, host, or guarantee production-ready software. It prepares structured implementation guidance for external engineering workflows.

## Project Understanding

Phase 6 adds deterministic understanding for one-line project ideas. The analyzer infers:

- detected project type
- domain
- target users
- likely user roles
- likely workflows
- core features
- likely data entities
- frontend needs
- backend/API needs
- infrastructure and testing assumptions

Supported project-type detection includes:

- backend platform
- AI application
- dashboard
- SaaS application
- mobile application
- ecommerce application
- marketplace
- generic web application

Unknown but meaningful project ideas fall back to `generic web application`.

## Build Pack Documents

The build-pack generator creates these deterministic markdown documents:

- `START_HERE.md`
- `COPY_THIS_PROMPT.md`
- `project_brief.md`
- `requirements.md`
- `mvp_scope.md`
- `architecture.md`
- `database_schema.md`
- `api_spec.md`
- `frontend_spec.md`
- `implementation_steps.md`
- `testing_plan.md`
- `deployment_plan.md`
- `assumptions.md`
- `coding_agent_prompt.md`

Each document uses the project understanding data and remains project-adaptive rather than hardcoded to a single example domain.

## ZIP Structure

The Phase 6 Coding Agent ZIP contains:

```text
START_HERE.md
COPY_THIS_PROMPT.md

generated_project/
  START_HERE.md
  COPY_THIS_PROMPT.md
  project_brief.md
  requirements.md
  mvp_scope.md
  architecture.md
  database_schema.md
  api_spec.md
  frontend_spec.md
  implementation_steps.md
  testing_plan.md
  deployment_plan.md
  assumptions.md
  coding_agent_prompt.md
  project_plan.md
  project_plan.json
```

The ZIP is generated by the export layer and reuses the existing project plan markdown and JSON serialization behavior.

`COPY_THIS_PROMPT.md` is the direct user handoff prompt. Users can paste it into Codex, Claude Code, Cursor, Copilot, Lovable, Bolt, Gemini, or a similar coding agent and attach the rest of the ZIP. It explicitly instructs the coding agent to build the requested application, generate source code, add build/runtime configuration, write tests, and avoid documentation-only responses.

`START_HERE.md` is the execution entry point. It instructs coding agents to create a runnable application source tree, build/runtime configuration, tests, and local run instructions instead of only summarizing the specification files.

## CLI, API, and Frontend

The CLI saves the existing JSON, Markdown, and Phase 5 Prompt Pack ZIP outputs, then also saves the Phase 6 Coding Agent ZIP.

The FastAPI backend exposes:

- `POST /generate-plan`
- `POST /generate-plan-zip`
- `POST /generate-build-pack-zip`
- `POST /generate-coding-agent-zip`

The frontend keeps the existing JSON, Markdown, and Prompt Pack ZIP downloads and adds a `Download Coding Agent ZIP` action that calls `/generate-coding-agent-zip`.

## Compatibility

Phase 6 preserves:

- existing planner behavior
- deterministic fallback behavior
- Phase 5 Prompt Pack ZIP behavior
- existing API plan generation behavior
- existing frontend export actions
- existing JSON and Markdown exports

The build pack is an additive export path. It does not replace the project plan or prompt pack.

## Non-Goals

Phase 6 does not include:

- automatic software generation
- automatic deployment
- cloud storage
- authentication
- persistence
- guided chat
- Jira integration
- background workers
- coding-agent API integrations

Generated build packs should be treated as implementation guidance that requires engineer review before use.
